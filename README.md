# 🦸 Superman Voxel Simulator

شبیه‌ساز سوپرمن در دنیای ماینکرافت — یک بازی مرورگری سه‌بعدی با Three.js، در **یک فایل**، بدون build step و بدون اینترنت.

> زبان بازی انگلیسی است؛ این مستندات فارسی‌اند.

---

## نحوهٔ اجرا

### روش ۱: باز کردن مستقیم فایل (ساده‌ترین)

۱. مخزن را کلون یا دانلود کنید:

```bash
git clone https://github.com/17mohammad1718-png/superman-voxel.git
cd superman-voxel
```

۲. `index.html` را باز کنید (دابل‌کلیک یا کشیدن داخل پنجرهٔ مرورگر).

۳. روی **START GAME** کلیک کنید.

> ✅ دابل‌کلیک واقعاً کار می‌کند: Three.js به‌صورت یک اسکریپت کلاسیک (`vendor/three.global.js`) بارگذاری می‌شود، نه ES Module. ماژول‌ها روی `file://` توسط CORS مرورگر بلاک می‌شوند و صفحه سیاه می‌ماند.
>
> ⚙️ به همان دلیل، تولید زمین در Web Worker **اختیاری** است: اگر مرورگر blob worker را روی `file://` نپذیرد (Chromium نمی‌پذیرد)، بازی بی‌صدا به تولید روی نخ اصلی با بودجهٔ هر فریم برمی‌گردد. هیچ مسیری وجود ندارد که بازی به‌خاطر نبود Worker متوقف شود.

### روش ۲: وب‌سرور محلی (توصیه‌شده برای توسعه)

```bash
npm start          # همان python3 -m http.server 8080
# یا
python3 -m http.server 8080
```

سپس **http://localhost:8080**. روی این حالت Worker هم فعال می‌شود.

### تست و CI

```bash
npm ci
npm test           # ۵۵ بررسی روی خودِ کد index.html
npm run vendor:check
```

`tools/smoke-test.js` اسکریپت **دست‌نخوردهٔ** داخل `index.html` را در jsdom با three.js واقعیِ `vendor/` اجرا می‌کند (فقط `WebGLRenderer` و canvas دوبعدی stub می‌شوند) و این‌ها را می‌سنجد: بوت، تولید زمین و قطعی‌بودن آن، کد Worker، greedy meshing، ری‌کست ووکسلی، قدرت‌ها، استریم چانک، ذخیره/بازیابی و تنظیمات.

علاوه بر اجرا، چهار بررسی ایستا هم انجام می‌شود (**۸۸ بررسی** در مجموع):

- **شیدرها**: هر ۶ مرحلهٔ GLSL (vertex/fragment برای زمین، آب و آسمان) با پارسر واقعی GLSL ES پارس می‌شوند، با همان declarationهایی که three.js به یک `ShaderMaterial` تزریق می‌کند. این جای خالیِ نبودِ GPU را تا حد syntax پر می‌کند.
- **سطح API**: هر ۳۷ نماد `THREE.*` که بازی استفاده می‌کند باید در بیلد r160ِ وندورشده وجود داشته باشد.
- **DOM**: هر ۴۷ شناسهٔ `$('id')` باید در مارکاپ وجود داشته باشد — غلط تایپی اینجا در بوت خودش را نشان نمی‌دهد، بلکه اولین‌بار وقتی آن هندلر اجرا شود (مثلاً کنترل لمسی) منفجر می‌شود.
- **هندسهٔ مش**: نرمال هندسیِ هر ۳۶٬۴۷۲ مثلث باید دقیقاً روی یکی از شش محور دنیا باشد و **هر شش جهت** حضور داشته باشند. اگر winding در مش‌ساز greedy برعکس بود، زمین به‌خاطر backface culling در مرورگر *نامرئی* می‌شد و هیچ تست دیگری آن را نمی‌گرفت. به‌علاوه: رأس‌ها روی گرید صحیح، ایندکس کاشی‌ها در محدودهٔ اطلس، و UVها مضرب صحیح کاشی.

تست یک نمونهٔ **دوم** هم با `matchMedia('(pointer: coarse)') === true` بوت می‌کند تا مسیر لمسی واقعاً اجرا شود (`IS_TOUCH` در jsdom همیشه false است، پس `initTouch()` بدون آن هرگز اجرا نمی‌شد): جوی‌استیک بازیکن را حرکت می‌دهد و با رهاشدن به مرکز برمی‌گردد، درگ روی نیمهٔ راست دوربین را می‌چرخاند، و هر پنج دکمه (شلیک، ساختن، پرش، پرواز، توقف) کار می‌کنند. مسیرهای تنظیمات هم پوشش داده شدند: تغییر شعاع رندر (با هیسترزیس `R+2`، پس افت ۵→۳ عمداً چیزی unload نمی‌کند)، تکمیل‌شدن مأموریت‌ها به ترتیب، و RESET WORLD که زمین را **دور بازیکن** بازتولید می‌کند نه دور مبدأ.

> ⚠️ چیزی که تست **نمی**سنجد: کامپایل واقعی شیدر روی GPU و ظاهر بصری (مرورگر headless در محیط CI نصب نمی‌شود). اگر صفحه سیاه یا سفید بود، خطای کامپایل را در کنسول F12 ببینید. فایل CI در `ci/ci.yml` است و همین دو دستور را اجرا می‌کند؛ چون باتِ بازکنندهٔ PR اجازهٔ نوشتن در `.github/workflows/` را ندارد، برای فعال‌سازی یک‌بار آن را کپی کنید:

```bash
mkdir -p .github/workflows && cp ci/ci.yml .github/workflows/ci.yml
```

## دنیا

- **بی‌نهایت و استریم‌شده**: چانک‌های ۱۶×۶۴×۱۶ اطراف بازیکن تولید و پشت سرش آزاد می‌شوند. مرزی وجود ندارد.
- تولید توپوگرافی با Perlin noise / fBm + نویز ridge برای کوه‌ها
- انواع بلوک: چمن، خاک، سنگ، آهن، الماس، چوب، برگ، شن، آب، بستر سنگ، برف، **یخ**، **آجر**
- دریا با ساحل شنی، کمربند سنگی کوهستانی، برف بالای خط برف
- درخت‌ها بدون بریدگی روی مرز چانک (هر چانک فقط بخش داخل خودش را می‌نویسد)
- معادن: آهن و الماس بر اساس hash مختصات (قطعی و مستقل از ترتیب تولید)
- فاصلهٔ رندر قابل تنظیم: ۳ تا ۱۲ چانک

### Seed

دنیا کاملاً قابل بازتولید است. seed پایین-چپ صفحه است؛ رویش کلیک کنید تا لینک دنیا کپی شود:

```
index.html?seed=4242
```

- **امتیاز**: آهن ۲۵، الماس ۱۰۰، یخ ۲، بقیه ۱–۲ امتیاز؛ در localStorage به‌عنوان highscore ذخیره می‌شود.

- **چرخهٔ شب و روز** ۵ دقیقه‌ای: آسمان گرادیانی، خورشید و ماه، ستاره‌ها، ابرهای متحرک، ساعت در HUD.

## فناوری و بهینه‌سازی

- Three.js r160 (محلی در `vendor/`، اسکریپت کلاسیک → سازگار با `file://`) · WebGL · بدون build step
- **Greedy meshing**: وجه‌های هم‌صفحهٔ هم‌کاشی و هم‌AO در یک `BufferGeometry` ادغام می‌شوند → **۱ تا ۲ draw call به ازای هر چانک**
- **بافت رویه‌ای**: اطلس ۲۵۶×۲۵۶ با ۱۵ کاشی ۱۶×۱۶ که پیکسل‌به‌پیکسل از hash مختصات ساخته می‌شود (بدون فایل تصویر)
- **Ambient Occlusion پخته‌شده در رأس‌ها** + سایه‌روشن سمتی وجه‌ها؛ هیچ نور پویا و shadow map روی زمین نیست
- **تولید در Web Worker** با fallback خودکار روی نخ اصلی
- **Voxel DDA** برای لیزر، برخورد دوربین و انتخاب بلوک
- **بازسازی تنبل چانک‌ها** با بودجهٔ سازگار با زمان فریم (اگر فریم کند شد، مش‌سازی کمتر)
- **heightmap کش‌شده در هر چانک** برای مینی‌مپ + `terrainHeight` خالص برای منطقهٔ بارگذاری‌نشده
- PRNG قطعی (hash مختصات) → دنیای seed-محور، مستقل از ترتیب تولید
- X-Ray با یک uniform (بدون تعویض متریال یا بازسازی چانک)

### نتایج اندازه‌گیری‌شده (خروجی `npm test`، seed=4242)

| معیار | مقدار |
|---|---|
| Draw call به ازای هر چانک | ۱ (زمین) + ۱ (آب) |
| مثلث با greedy meshing | ۳۶٬۴۷۲ |
| مثلث با مکعب به ازای هر بلوک | ۴۸۶٬۷۲۰ → **۱۳٫۳ برابر کمتر** |
| زمان تولید یک چانک | ~۳٫۲ ms |
| زمان مش‌سازی یک چانک | ~۶ ms |
| بوت (۹ چانک + اولین فریم) | ~۰٫۴ ثانیه در jsdom |

## فایل‌ها

```
superman-voxel/
├── index.html              ← بازی (single-file، ~۲٬۹۰۰ خط)
├── vendor/
│   ├── three.global.js     ← چیزی که index.html بارگذاری می‌کند (generated — ویرایش نکنید)
│   └── three.module.js     ← بیلد رسمی ES-module آپاستریم three@0.160.0 (منبع بازتولید)
├── tools/
│   ├── make-three-global.js← ماژول → بیلد گلوبال: node tools/make-three-global.js [--check]
│   └── smoke-test.js       ← تست دود: npm test
├── ci/ci.yml               ← workflow آماده (یک‌بار به .github/workflows/ کپی شود)
├── package.json            ← فقط devDependency (jsdom، پارسر GLSL) برای تست؛ بازی به آن‌ها نیاز ندارد
├── LICENSE                 ← MIT (+ یادکرد three.js)
├── README.md
├── REVIEW.md               ← بررسی فنی نسخهٔ اول و وضعیت هر مورد
└── UPGRADE_PLAN.md         ← نقشهٔ راه و وضعیت فازها
```

اگر روزی نسخهٔ Three.js را عوض کردید، `vendor/three.module.js` را با بیلد جدید جایگزین کنید و `npm run vendor:build` را بزنید (`npm run vendor:check` در CI مطمئن می‌شود فایل تولیدشده به‌روز است).

## عیب‌یابی

| پیام / علامت | معنی | راه‌حل |
|------|--------|--------|
| ⚠️ Three.js failed to load — *could not fetch* | `vendor/three.global.js` کنار `index.html` نیست | کل مخزن را کلون کنید، نه فقط فایل HTML |
| ⚠️ Three.js failed to load — *did not define THREE* | فایل ناقص یا کش‌شده | `vendor/` را دوباره کپی کنید و Ctrl+Shift+R بزنید |
| ⚠️ WebGL is not available | مرورگر context وب‌جی‌ال نمی‌دهد | Hardware acceleration را روشن کنید؛ در VM با `--ignore-gpu-blocklist` |
| ⚠️ The game failed to start | خطای واقعی کد با نام فایل و شمارهٔ خط | متن پنل و کنسول F12 را بخوانید |
| «DRAG TO LOOK» بالای صفحه | pointer lock در iframe/محیط امبدد مسدود است | با نگه‌داشتن کلیک چپ ماوس را بکشید |
| کنترل‌ها کار نمی‌کنند | صفحه فوکوس ندارد | ابتدا روی صفحهٔ بازی کلیک کنید |
| افق دیر پر می‌شود | فاصلهٔ رندر زیاد یا دستگاه کند | در منوی ESC فاصلهٔ رندر یا Resolution را کم کنید |
